# ADR 0005：用有界 MTA 查询隔离 UIA 卡死

Status: Accepted

UI Automation 查询会跨进程进入目标应用的 Provider。目标无响应或 Provider 有缺陷时，托管取消令牌不能安全中断已经进入 COM 的同步调用；如果直接在长期工作线程上查询，一次卡死就会永久停止后续判断。

InputCue 因此让完整观察在一条可复用的后台 MTA 查询线程内串行执行，并由调度器等待一个短而有界的时间。正常完成的查询继续复用该线程，避免每次创建托管线程后原生句柄等待 GC 才释放。超时结果统一标记为 `ProbeIssue.TimedOut` 并隐藏提示。超时线程仍存活时，调度器绝不启动第二个查询；线程结束后还需经过冷却时间才允许恢复尝试，随后淘汰旧线程并创建新 MTA 查询线程。已经超时的迟到结果始终丢弃，不能与新的焦点或窗口事实组合。

这个方案不能强制终止有问题的 COM 调用，但能保证 UI 线程不被阻塞、卡死线程数量有上限，而且恢复行为可测试。查询线程和两个唤醒句柄在观察会话内长期复用；只有发生超时并完成隔离恢复时才替换线程。超时阈值属于内部诊断参数，需根据真实应用 Trace 调整，不暴露成普通用户设置。
