# 0007：用事件驱动的应用停留会话限制上下文重播

## 状态

已接受

## 决策

“更少显示”只限制 `ContextEstablished` 造成的重复提示。同一应用连续位于前台期间，首次具备完整显示条件的输入上下文正常提示，之后的输入目标或焦点变化不再重播；输入状态变化始终按既有规则提示。切换到其他应用后会话结束，再次返回时允许新的首次提示。

应用停留会话由现有 WinEvent、UI Automation 焦点事件和诊断观察推进。该功能不创建定时器，不增加采样频率，也不长期轮询前台窗口。无法识别应用身份时采用保守策略，不抑制提示。

## 影响

无可用锚点、输入状态未知等观察不会消耗首次提示机会。点击锚点降级仍只负责补齐位置，后续显示决策继续进入同一个 `IndicatorSession`，因此现有资格判断、显示时长、输入活动隐藏和定位规则不变。

## 补充（2026-08-28：三档同应用提示模式）

原始决策的“首次之后一律抑制”保留为其中一档，并扩展为用户可选的三档模式（`AppStayPromptMode`）：

- `Always`：不经过本策略，每次 `ContextEstablished` 都重播（等价于原始的“更少显示”关闭）；
- `AfterDelay`：首次机会正常提示；同应用停留期间，距上次实际提示满设定延时（默认 300 秒，允许 10–3600 秒）后的下一次提示机会重新重播，并重置计时；本档为默认档；
- `Never`：即原始决策的行为，首次之后不再重播。

延时自策略放行该次提示机会的时刻起算，因此仍不创建定时器、不增加采样频率；切换应用、重置策略或不满足显示条件的观察都会照旧清空或跳过会话状态。旧配置中的布尔 `LessDisplay` 键在加载时映射为 `Never`（true）或 `Always`（false），首次保存后以新字段落盘。
