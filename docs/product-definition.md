# 产品边界

## 一句话定义

InputCue 在 Windows 上只做一件事：当用户确实位于可编辑输入位置时，以低干扰方式提示当前中文、英文或大写状态。

## 核心问题

现有工具通常把“有一个坐标可以放提示”误当成“用户正在输入”。这会造成两个典型误报：

- 在网页拖选只读文字时，没有插入光标却出现输入法提示；
- 鼠标悬停在对话框标签或其他 I 型指针区域时，提示错误出现。

InputCue 的差异化不在于更多样式，而在于更可靠地决定“不显示”。

## 产品原则

1. 精确优先于覆盖。无法确认时隐藏，不猜测。
2. 可显示性与定位分离。鼠标只能作为已确认可编辑后的定位降级，不能证明目标可编辑。
3. 默认值应可直接使用。安装、启动、看到效果，不要求先读教程。
4. 兼容策略必须可复现。每个应用特判都要有场景、版本边界和回归用例。
5. 被动提示优先。V1 不修改用户的输入法状态。
6. 隐私默认关闭采集。不得记录按键、选中文本、窗口标题或输入内容。

## V1 范围

### 状态

- 中文；
- 输入法英文；
- 英语（美国）美式键盘；
- Caps Lock 大写。

### 显示

- 输入光标旁的小圆点或短标签；
- 输入法状态变化或一次输入会话首次建立时短暂显示；
- 提示出现时读取一次锚点，并在本次显示期间固定位置；
- 同一输入目标内的光标移动、联想选区和拖动选区只更新上下文，不重复提示；
- 开始输入后隐藏，并在近期持续输入期间抑制由焦点或 UIA 身份抖动造成的重播；
- 可选择始终显示；
- 无可靠光标坐标时，在已确认可编辑的前提下允许使用有限降级位置。

### 设置

- 三种状态颜色；
- 大小、距离、显示时长；
- 开机启动；
- 暂停提示；
- 按应用禁用；
- 导出脱敏诊断信息。

### 首批兼容场景

- Windows 记事本；
- Edge / Chrome 普通输入框与网页只读文本；
- VS Code 编辑器；
- Windows Terminal；
- 微信文本输入框；
- Word 或 WPS 文字的基础编辑场景；
- 原生 Windows 对话框中的编辑框、标签和按钮。

## V1 明确不做

- 自动切换中英文；
- 规则引擎、正则窗口匹配和动态热键；
- 全局键盘 Hook；
- 读取或复制选中文本；
- 浏览器扩展、Office/WPS COM 取词、剪贴板取词；
- JAB/JetBrains 深度适配；
- 图片主题、插件系统、AI、按键统计；
- 为获得管理员窗口信息而自动提权；
- 承诺所有第三方输入法和所有应用均可用。

## 成功标准

V1 的首要指标不是“出现率”，而是“错误出现率”。在受支持测试矩阵中：

- 静态网页拖选、对话框标签悬停、按钮悬停的误报为 0；
- 焦点快速切换时，旧异步结果导致的误报为 0；
- 所有显示决策都有稳定原因码；
- 用户无需理解进程名、窗口类、UIA、IME 状态码或 DPI 偏移。
