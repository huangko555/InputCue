# 开发计划

## 总体策略

先证明“什么时候绝不显示”，再实现“如何显示得漂亮”。第一条工程主线是可回放的输入上下文引擎，第二条才是提示层和设置界面。

预计投入：一名开发者约 6–8 个专注周；若以业余时间推进，建议按 10–12 周安排。每个阶段都设继续/停止门槛，避免 UI 完成后才发现底层不可用。

## 当前基线（2026-08-16）

当前实现基线：截至本文件所在提交。

已验证：

- 记事本中的微软拼音中文/英文状态可以通过默认 IME 窗口和转换模式归类；
- Chrome/Edge 中部分标准 `Edit` 控件可以识别为 `EditableCaret`，Chrome 当前主要依赖 MSAA Caret，证据等级为 `Degraded`；
- Chrome Google 搜索框的可写 `ComboBox` 已通过真实前台 Trace 验证，可稳定区分可编辑 Caret 与网页正文；
- 静态网页正文和非编辑控件不会因为鼠标悬停被当成可编辑光标；
- 真实 Trace 暴露的 UIA 整控件矩形会在独立 Win32/MSAA Caret 位于其中时安全回退；
- 95 个自动化测试、Release 构建和格式检查通过。

已确认但尚未解决：

- WPS 正文点击后画面上有光标，但它由 WPS 自绘，UIA、Win32 Caret、MSAA Caret 和 IMM 组合点均未提供可用锚点；
- Windows Terminal 使用 `XAML + TermControl + ControlType.Text`，当前策略会判定为 `NoEditableFocus`；
- 可编辑控件存在非折叠选区时目前隐藏，地址栏全选等场景尚未支持提示。

这些问题必须分别建立脱敏 Trace 后再改规则，不能用一个“放宽所有控件”的特判解决。

## 阶段 0：工程基线（1–2 天）

### 工作

- 根据 ADR 0003 最终确认技术栈；
- 初始化 Git 和 .NET solution；
- 建立 `src/`、`tests/`、`docs/` 结构；
- 开启 nullable、静态分析、统一格式和 Release 构建；
- 设置 x64 与 Per-Monitor DPI Awareness V2；
- 建立最小 CI：还原、构建、单元测试；
- 定义版本号、设置 schema 和原因码规范。

### 验收

- Debug/Release 均可在干净环境构建；
- 一个空 WPF 程序可启动和退出，无托盘残留进程；
- 测试项目和 CI 通过；
- 尚不包含真实探测或提示 UI。

### 门槛

若技术栈不能稳定调用 UIA COM、Win32 和无激活窗口，则在此阶段更换，不进入功能开发。

## 阶段 1：只读诊断探针（3–5 天）

### 工作

- 实现前台窗口、焦点、进程归属和 Generation；
- 采集 UIA 可编辑、只读、Selection、Caret 能力；
- 采集 Win32/MSAA Caret 作为对照；
- 输出结构化原因码和来源耗时，不绘制提示层；
- 实现脱敏 Trace 录制与回放；
- 建立五个首批黄金场景。

### 黄金场景

1. 浏览器输入框获得焦点：判定 `EditableCaret`；
2. 静态网页拖选文字：判定 `ReadOnlySelection`，不因 I 型指针改变；
3. 对话框标签/按钮悬停：判定 `NoEditableFocus`；
4. 对话框编辑框获得焦点：判定 `EditableCaret`；
5. 查询未完成时快速切换窗口：旧 Generation 结果被丢弃。

### 验收

- 五个场景均能生成可解释 Trace；
- Trace 不含文本、按键、窗口标题和用户路径；
- 同一 Trace 回放结果确定且可断言；
- 静态拖选和悬停误报为 0。

### 门槛

若浏览器和原生对话框的正负场景仍无法稳定区分，暂停 UI 开发，继续收敛输入上下文模型。

## 阶段 2：纯状态机（4–5 天）

### 工作

- 实现 Eligibility 状态模型和 ObservationValidator；
- 实现 Generation、超时、取消、去抖和结果淘汰；
- 实现 `IndicatorSession` 的显示/隐藏/淡出状态；
- 建立单位测试、表驱动测试和属性测试；
- 将阶段 1 的 Trace 固化为回归资产。

### 必测不变量

- `Unknown` 永不显示；
- 只读 Selection 永不显示；可编辑 Selection 只有在取得安全锚点后才允许显示；
- 没有可编辑证据时，即使有鼠标坐标也不显示；
- 旧 Generation 永不改变新状态；
- 状态来源超时不会阻塞 UI；
- 重复事件不会无限延长或闪烁提示。

### 验收

- 状态机不依赖真实 Windows API 即可完整测试；
- 所有转换都有 Reason Code；
- 随机事件序列不能破坏上述不变量。

## 阶段 3：Windows 生产 Adapter（1–2 周）

### 工作

- 完成专用 STA 调度器和有界队列；
- 实现 UIA 主路径、Win32/MSAA 补充路径；
- 已实现微软拼音中文/英文、美式键盘和 Caps Lock 四态；美式键盘按 `0x0409` 独立分类，Caps Lock 由 UI/STA 线程读取并仅覆盖可见状态；
- 增加输入法和框架来源健康度、超时熔断；
- 按兼容矩阵测试首批应用；
- 仅在有 Trace 和回归用例后增加应用画像。

### 首批支持层级

| 层级 | 场景 | 要求 |
|---|---|---|
| A | 记事本、原生编辑框、已验证的 Edge/Chrome `Edit` 输入框 | V1 发布前必须通过 |
| B | Google 类网页 `ComboBox`、VS Code、微信 | 有明确正负 Trace 后决定是否进入 V1 |
| C | Windows Terminal `TermControl`、Word/WPS 基础编辑 | 单独适配；不能稳定时默认隐藏 |
| Deferred | JetBrains/JAB、游戏、远程应用、自绘控件 | V1 不承诺支持 |

### 验收

- A 级场景全通过；
- B 级场景即使无法定位，也不会在只读区域误报；
- 权限不足、控件不可访问和超时均安全隐藏；
- 不要求管理员权限，不安装系统服务或注入 DLL。

## 阶段 3A：兼容性缺口收敛（预计 1 周）

该阶段必须在提示层开发前完成，避免把错误的输入上下文传给 Overlay。

### 3A.1 网页可编辑 `ComboBox`

- 当前进度：候选策略、边界测试和真实前台 Google Trace 已完成；网页正文和建议项负例保持隐藏；
- 将 `ComboBox` 仅在存在可写 `ValuePattern` 且 `IsReadOnly=false` 时纳入候选；
- 增加 Google 搜索框/自动补全框正例；
- 增加普通下拉框、只读 ComboBox 和网页按钮负例；
- Caret 仍必须来自 UIA、Win32 或 MSAA，不能用鼠标坐标补齐。

### 3A.2 可编辑选区

- 当前进度：分类、显示会话和 generation 去抖已实现；原生 WPF 无安全锚点时保持隐藏，已有 Edge Trace 可通过 MSAA Caret 显示；地址栏真实前台验证待完成；
- 区分 `EditableSelection` 与 `ReadOnlySelection`；
- 产品规则：可编辑输入框内即使文字被全选，用户仍然可以直接输入，因此允许提示；
- 只在输入会话首次建立或输入法状态变化时触发提示；选区建立、联想文字选中和拖动选区只更新上下文与锚点，不重播提示；
- 优先尝试 `TextPattern2.GetCaretRange` 获取活动插入点；
- 若活动插入点不可用，才尝试当前可编辑选区的安全边界作为锚点；
- 没有安全锚点时保留 `EditableSelection` 诊断和空 Anchor，显示层按 `PositionUnavailable` 隐藏；
- 网页正文拖选仍必须保持隐藏。

验收场景至少包含：

- Chrome/Edge 地址栏点击后全选：允许显示一次状态提示；
- 普通网页 `input`/`textarea` 中按 `Ctrl+A`：允许显示一次状态提示；
- 记事本/WPS 文档中全选：有安全锚点时允许显示；
- 网页只读正文拖选：始终隐藏；
- 编辑框拖动选区过程中：不使用鼠标位置，不跨控件复用旧锚点。

### 3A.3 WPS 文档

- V1 暂缓：保留现有安全降级和只读 TSF 实验，不继续引入鼠标定位、注入或 Hook；
- 当前进度：已完成 3 次连续 20 秒脱敏 Trace；修复 WPS 顶层窗口、UIA 焦点元素和 `hwndFocus` 属于同一可执行文件的多进程身份校验；
- WPS 正文稳定暴露为 `wps.exe + Qt + KxWpsView + ControlType.Group + ValuePattern(IsReadOnly=false)`，已纳入窄范围应用画像；
- 该画像当前可确认 `HasEditableFocus=true`，但 UIA TextPattern、Win32 Caret、MSAA Caret、IMM 组合点均为空，最终状态为 `PositionUnknown`，提示层必须继续隐藏；
- 不引入远程线程 Hook、注入 DLL 或鼠标坐标伪装 Caret；若后续无法找到可审计锚点，将 WPS 记录为 V1 不支持。

### 3A.4 Windows Terminal

- 当前进度：已纳入窄范围画像并完成真实前台复测；`WindowsTerminal + XAML + TermControl + ControlType.Text + IsReadOnly=false` 可确认 `HasEditableFocus=true`，但 20 条连续采样均为 `PositionUnknown`，`TextPattern2=PatternUnavailable`，Win32/MSAA Caret 为空；
- V1 暂缓：微软 Terminal 源码虽有通用 UIA TextPattern/Selection provider，但当前版本没有向外部探针提供可用插入光标矩形；不使用鼠标位置、输出区域或旧坐标降级；
- 只针对 `FrameworkId=XAML + ClassName=TermControl` 评估可编辑资格；
- 不把所有 `ControlType.Text` 当作输入控件；
- 若 Terminal 没有稳定 Caret 来源，记录为 `PositionUnknown` 并保持隐藏。

### 3A.5 WebView2 / ProseMirror

- 当前进度：已用 Bitty Note 1.3.9 完成真实前台采集，连续 10 条观察均为 `EditableCaret / EditableCaretConfirmed`；UIA TextPattern 与 MSAA 返回一致的 `2×20` Caret；
- WebView2 的前台窗口属于宿主进程，UIA 焦点属于两级子渲染进程；只有焦点进程沿系统进程父链可追溯到当前前台进程时才接受，不能仅凭 `msedgewebview2.exe` 名称放宽身份校验；
- ProseMirror 画像仅接受 `FrameworkId=Chrome + ControlType.Group + ProseMirror + ProseMirror-focused + TextPattern`，外层仍要求键盘焦点和明确的 `IsReadOnly=false`；
- 普通网页 Group、未聚焦或只读 ProseMirror、无 TextPattern 的近似控件继续保持隐藏；
- 已保存脱敏黄金 Trace，并为宿主父链方向和画像近似项建立回归测试。

### 3A 验收门槛

- 每个缺口至少有一个正例和一个负例 Trace；
- Chrome/Edge 网页输入框、网页正文拖选和普通下拉框不能互相误判；
- WPS 至少两次连续采样结果一致，或明确记录为 V1 不支持；
- Terminal 不因可写文本标签、输出区域或鼠标悬停产生 `EditableCaret`；
- 所有新增应用特判都限制在 `InputCue.Windows` 内，并有对应单元/回放测试。

焦点触发补强：UIA 焦点/选区事件之外，通过独立消息线程上的 WinEvent 监听前台窗口和原生焦点变化；事件缺失时每 2 秒进行一次完整兜底观察。已确认可编辑的上下文每 200ms 轻量刷新输入状态；新可编辑目标首次坐标为空时最多进行 3 次、间隔 75ms 的布局重试。该重试有明确上限，不能让 WPS、Terminal 等长期无坐标目标持续高频探测。

## 阶段 4：提示层与最小设置（约 1 周）

当前实现策略：先用固定圆点、固定四态颜色、默认 1 秒显示、输入后最短显示 300ms 和单一启用开关跑通端到端流程。同一输入目标只提示一次，编辑活动后的 1.5 秒上下文重播抑制仅作为 UIA 身份抖动的低成本兜底，不增加轮询或 Hook；主题、颜色、位置模式、始终显示、托盘和持久化均在基础行为验证后再逐项加入。

当前进度：可靠单实例已实现。正常 UI 重复启动时，第二个进程只发送一次窗口唤醒信号并退出；诊断命令不受单实例约束。协调线程通过命名内核事件阻塞等待，不进行轮询。提示层已统一使用物理屏幕像素：按 Caret 所在显示器读取工作区和 DPI，只缩放视觉间距与提示尺寸；右侧空间不足时改放左侧，并在上下边缘夹紧。100%、125%、150%、200% 和负坐标副屏已有纯逻辑回归测试，跨屏视觉结果仍需实机验收。系统托盘已接入：关闭主窗口仅隐藏，托盘可打开设置、暂停或继续提示以及显式退出；托盘状态直接跟随探针监听状态，不建立第二份状态。启用状态、显示时长和输入后最短时长已持久化到本地 JSON；写入采用同目录临时文件后原子替换，缺失、损坏或越界配置均安全回退默认值，暂停状态保持为不跨重启的临时操作。开机启动使用当前用户 Run 注册表项，启动命令带 `--background`；后台启动直接创建隐藏消息窗口，不闪现设置窗口，手动启动仍显示窗口。

### 工作

- 实现不激活、鼠标穿透的 WPF 提示层；
- 实现中文、英文、大写样式和实时预览；
- 实现大小、距离、时长、始终显示、暂停和开机启动；
- 实现多显示器边界约束和 DPI 切换；
- 实现托盘菜单和可靠单实例；
- 配置损坏时安全恢复默认值。

### 验收

- 提示层不抢焦点、不阻断点击、不进入 Alt+Tab；
- 100%、125%、150%、200% 缩放及跨屏移动无明显偏移；
- Explorer 重启、睡眠恢复和显示器重连后可恢复；
- 不打开设置也能正常使用。

- Adapter 超时、异常、取消和熔断；
- DPI 坐标换算和工作区边界；
- 快速焦点切换与高频状态变化压力测试。

### 手工/系统验证

- 8 小时日常使用和 24 小时空闲/周期活动 soak；
- 多显示器、缩放切换、睡眠/唤醒、RDP 重连；
- Explorer 重启、输入法切换、应用崩溃；
- 普通进程面对管理员窗口；
- 全屏视频和游戏类窗口默认暂停；
- 安装、升级、卸载和开机启动。

进行 VM 测试前需在对应任务中明确授权启动 Codex Test VM；没有授权时使用本机只读验证或人工测试清单。

### 暂定质量预算

- 支持矩阵内静态拖选/悬停误报：0；
- 旧 Generation 发布：0；
- 状态变化到提示更新：参考机器 p95 ≤ 150 ms；
- 空闲 CPU：参考机器 p95 ≤ 0.5%；
- 常驻工作集：参考机器 ≤ 100 MB；
- 24 小时 soak：无崩溃、无不可恢复卡死；
- 默认日志：0 条用户文本或按键内容。

性能数字在阶段 1 记录参考硬件后可调整一次，之后作为回归门槛。

2026-08-16 当前诊断版空闲基线：20 逻辑处理器上连续 15 秒平均 CPU 为 0.806%，工作集从 157.8 MB 增至 159.2 MB，私有内存从 96.3 MB 增至 97.3 MB。对照测量中，暂停并最小化诊断窗口为 0.271%，探针运行并最小化为 1.035%；为事件触发的完整 UIA 观察增加 150ms 最小间隔后，后者降至约 0.776%。事件风暴回归测试从 360ms 内 9 次完整观察收敛到最多 5 次。额外区分选区/焦点事件以及移除重复 UIA Focus 订阅均未带来可测收益，已撤回。后续后台稳态采样发现旧实现每次完整观察创建短生命周期托管线程，低分配进程中线程原生句柄等待 GC，导致句柄约每 10 秒增长 14。改为观察会话复用一条 MTA 查询线程后，同一反馈循环降为 10 秒增长 2，随后 20 秒样本句柄保持 832 不变，CPU 为 0.105%，线程保持 29；无事件兜底恢复和连续 10 次暂停/继续已有回归测试。CPU 与工作集的完整结论仍需更长样本和采样分析器，不能靠短时数字结项。

- 完成安装包、版本说明、隐私说明和问题模板。

### 发布门槛

- A 级矩阵全部通过；
- 无 P0/P1 崩溃、焦点干扰或隐私问题；
- 连续 7 天无新增可复现的静态拖选/悬停误报；
- 新用户不看教程可完成安装并看到正确提示；
- 已知不支持场景能安全隐藏并在文档中说明。

## 兼容性矩阵格式

后续在 `tests/compatibility/` 中保存机器可读矩阵，每条至少包含：

- 应用名和版本；
- UI 框架；
- Windows 版本和缩放；
- 输入法和版本；
- 场景步骤；
- 预期 Eligibility、Anchor 来源和 Reason Code；
- 实际结果与对应 Trace；
- 是否允许进入应用画像。

重点必须同时覆盖正例和负例。只有“输入框能显示”而没有“静态文本不显示”的测试不算兼容通过。

## 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| UIA 调用卡住或返回动态失效对象 | 延迟、线程堆积 | 专用 STA、有界队列、短超时、Generation、熔断 |
| 自绘/Electron/终端不暴露标准 Caret | 无法定位 | 已确认可编辑后有限降级；否则隐藏 |
| 输入法状态实现各异 | 状态错误 | V1 先支持微软拼音；按输入法建立实测画像 |
| 多 DPI 坐标空间混用 | 跨屏偏移 | PMv2、统一物理坐标、矩形合理性校验 |
| 管理员权限边界 | 无法探测高权限窗口 | 不自动提权，隐藏并给出原因码 |
| 应用特判持续增长 | 可维护性下降 | Trace + 回归准入；优先修通用模型；标版本边界 |
| 全局 Hook 引发安全/游戏冲突 | 兼容和信任风险 | V1 不使用全局键盘 Hook，不注入进程 |
| 诊断泄露输入内容 | 隐私风险 | 结构化白名单字段、环形缓冲、主动导出、测试扫描 |

## 每阶段完成定义

一个阶段只有同时满足以下条件才算完成：

- 实现与产品边界一致；
- 相关自动测试通过；
- 新的兼容知识已进入 Trace、矩阵或 ADR，而不是只存在于代码注释；
- 失败场景有可解释 Reason Code；
- 文档与实际行为同步；
- 没有为未来假设添加未使用的扩展点。

## V1 之后再评估

按真实反馈排序，而不是预先实现：

- 更多输入法识别；
- JetBrains/JAB；
- 单应用“跟随光标/固定位置/禁用”的极简兼容设置；
- 自动切换输入状态；
- 更新机制与代码签名。

其中自动切换必须单独立项，因为它会从被动提示变为主动修改用户状态，风险模型完全不同。
